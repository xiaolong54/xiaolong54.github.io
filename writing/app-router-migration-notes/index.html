Next.js App Router 迁移踩坑记录

把一个两万行的 Pages Router 项目迁到 App Router，用了一周。这里是值得提前知道的七件事。

前端Next.js

迁移前我读了不少「五分钟迁移」的文章，真正动手才发现那都是玩具项目。下面是我希望一开始就有人告诉我的事。

值得提前知道的七件事

  1. 01服务端组件里读不到 `window`。任何依赖浏览器的模块都要用 dynamic(..., { ssr: false }) 隔离。
  2. 02useSearchParams 会让整棵树退回客户端渲染**，除非外面套一层 <Suspense>。
  3. 03样式表会跟着路由预加载，第三方的全局 CSS 不要在布局里随意引入。
  4. 04中间件跑在 Edge 运行时，Node 专有的 API 在里面不可用。
  5. 05路由处理器的缓存是默认开的，动态接口记得加 export const dynamic = 'force-dynamic'。
  6. 06`useEffect` 在开发模式下会执行两次，那是严格模式，不是你的 bug。
  7. 07404 要从根布局返回，不要在页面组件里手动渲染一个「找不到」的界面。

值不值得

值得。迁完之后首屏的 JS 体积少了 38%，布局不再随路由重渲染，流式加载让页面「出现」的时间提前了将近一秒。但请别在赶版本的时候做这件事。
